# 会议意见在 Linux Lab 中的落实

本轮仅改 Linux Lab；机器学习 demo 和跨课程平台另建仓库开展。设计先对照原始研究与现成题目系统，再确定模型与本地程序的职责，依据和局限见[设计说明](DESIGN.md)与[来源核对](../research/SOURCES.md)。

| 会议方向 | 当前设计与实现范围 | 证据边界 |
| --- | --- | --- |
| 情境式实践与原生命令 | 真实 Bash；原生帮助入口；lab 标注为平台功能，参数原词与助记笔记作为中文补充 | 换主题不等于教学效果已改善 |
| 按兴趣组织情境 | 新周目由模型先问兴趣，再按自由回答生成任务动机和主题对象；四个内置主题仅为离线示例 | 自由题材输入不保证每次都能生成合格实例 |
| 知识、任务与情境分离 | 九项稳定任务合同规定目标、知识点、证据和依赖；模型填写12类语义对象与任务故事，本地编译34项名称和材料 | 模型不能修改拓扑、隐藏结构、权限、字段约束与判题 |
| 生成质量控制 | 本地结构检查、独立模型语义复核、最多一次带诊断重生成，通过后冻结实例与合同版本/hash | 模型复核仍可能漏判；结构合格不证明语义完美或难度等值 |
| 跨知识点错误反馈 | 九关检查使用结构化错误类别，关联15个知识点；同一错误可关联多个知识点 | 原因是待核实假设 |
| 个性化学习手册 | 根据检查与求助记录生成手册和复习清单 | 不生成掌握百分比，不补造旧记录 |
| 可控 AI 与递进提示 | API 写入本地 JSON；模型提供情境和概念解释，本地提供技术要求、单步提示与判题 | 概念讲解失败回退本地；情境生成失败明确中止，不冒充成功 |
| 断点记忆与复习 | 保存实例、映射、诊断、提示级别和复习记录；续学不重复问兴趣或联网生成 | 复习间隔为规则，不是已实测的遗忘曲线 |
| 操作轨迹与反馈 | 开启后记录命令类别、选项、对象角色和有限文件状态，与后续检查结合 | 不捕获逐键修改、停顿、Vim 内部操作或认知过程 |

情境数据流：固定任务合同 → 模型问兴趣 → 自由回答 → 语义方案 → 本地编译和结构检查 → 独立语义复核 → 必要时一次带诊断重生成 → 冻结实例 → 建立真实文件 → 学生操作。失败不替换旧周目；显式指定本地情境可以离线创建。

学习支持数据流：本地检查项 → 稳定错误代码 → 观察类别与候选知识点 → 最近操作证据 → 单步提示 → 学习手册与复习。模型只接收规定用途的主题、合同摘要或学习摘要，不读取答案存档，也不决定通过与否。

新生成材料使用中性配置状态 active/deliver，旧局与旧离线包兼容 rescue/evacuate。已有局切换故事继续使用原文件与进度，不构成新的练习实例；新实例需要新建周目。研究支持应关注操作关系而非装饰性换词，但这套 Linux 设计的迁移效果仍待学生试验。

多用户容器部署、跨智能体共享画像、视频/案例推荐与课堂效果验证不属于已完成能力。工程回归、本地模拟 API 与真实服务试验各自说明不同范围，具体已做结果以[验证记录](../VALIDATION.md)为准。
