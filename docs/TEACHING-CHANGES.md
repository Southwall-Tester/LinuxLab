# 会议意见在 Linux Lab 中的落实

本轮仅改 Linux Lab；机器学习 demo 和跨课程平台另建仓库开展。

| 会议方向 | 本轮实现 | 验证边界 |
| --- | --- | --- |
| 情境式实践与原生命令 | 保留真实 Bash；明确 lab 是实验辅助命令；终端叙事提供三种模板 | 模板不同不代表教学效果不同 |
| 跨知识点的错误反馈 | 九关检查使用结构化错误类别，映射 15 个知识点；同一错误可关联多个知识点 | 归因是待核实假设 |
| 个性化学习手册 | 根据本局检查、求助记录生成手册与复习清单 | 不生成掌握百分比，不补造旧记录 |
| 可控 AI 与递进提示 | 本地 JSON 配置兼容 API；按需概念解释；本地单步提示；失败回退 | 输出过滤不保证语义正确 |
| 断点记忆与复习 | 保留诊断、提示级别、复习记录；无关数据小题和间隔安排 | 间隔为规则，不是经实验拟合的遗忘曲线 |
| 操作轨迹与个性化反馈 | 开启后记录命令语义、选项、对象角色和有限文件状态，结合后续检查选择反馈重点 | 不捕获逐键修改、停顿、Vim 内部操作或认知过程 |
| 知识与情境解耦 | knowledge.py 定义概念与复习；scenes.py 管理叙事；orbit.py 本地判题 | 暂未生成任意兴趣场景，也未改写实际文件名 |

数据流：本地检查项 → 稳定错误代码 → 观察类别与候选知识点 → 与最近操作证据交叉核对 → 单步提示 → 本局学习手册与复习。模型只接收经筛选的摘要，不接触答案存档，也不决定是否通过。

学习记录是文件结果与有限操作观察的证据。通过关卡不能推断某条命令确实被使用、独立完成或长期学习效果。操作证据不足时，系统必须保留不确定性。

多用户容器部署、跨智能体共享画像、视频/案例推荐、任意场景生成及课堂教学效果验证均不属于本轮已完成能力。接入平台前应分别设计接口、部署隔离与真实用户验证，不把原型设想写成成果。
