# ORBIT 教学设计与教师说明

## 目标与边界

对象是看过指定入门视频、尚未熟练使用终端的学生。目标是让学生通过真实文件操作理解路径、复制与移动、通配符选择与删除边界、归档、日志时序、编辑模式、权限和进程观察，并完成一次综合交付。

实验借用 Bomb Lab 的分阶段推进和现场线索，难点在“观察—操作—检查—修正”，不要求猜谜知识或编程。开源的本地判题程序可以被阅读、修改；本项目适用于练习与形成性评价，不作为防作弊考试环境。

## 视频范围映射

分集元数据来自 B 站公开接口。总长 3293 秒，约 54 分 53 秒，2 倍速约 27 分 27 秒。映射以已核实的分集主题为基础；不声称逐句复刻讲解顺序或覆盖每个参数。视频首帧和第六分集 150 秒抽样画面另用于确认 top、chmod。

| 视频分集 | 时长 | 本 Lab |
| --- | --- | --- |
| P1 cd 命令和 mkdir 命令常见用法 | 8:12 | 第 1 关路径定位、创建多层目录 |
| P2 ls 命令和 cp 命令常见用法 | 14:38 | 第 1 关隐藏信标，第 2 关完整备份 |
| P3 mv、rm、tar 命令常见用法 | 6:55 | 第 3、4、9 关移动、删除、解包与打包 |
| P4 cat 命令和 tail 命令常见用法 | 7:20 | 第 4、5 关短文本与长日志，第 8 关可选跟随 |
| P5 vim 文本编辑器基本用法 | 5:45 | 第 6、9 关编辑配置 |
| P6 文件权限管理 | 6:17 | 第 7 关 chmod、rwx 与数值权限 |
| P7 性能监控和压力测试 | 5:46 | 第 8 关 top 与限时低占用探针 |

视频标题中的“11 个命令”没有单独的官方完整清单可直接读取。本 Lab 将前五分集明确出现的 10 个命令与第七分集首帧的 top 作为核心 11 个，同时覆盖权限章节的 chmod；pwd、./脚本和命令替换是必要辅助。压测部分改为自动结束的低占用练习探针，不复现满载压测；其目的是学习观察进程而非测量机器性能。

## 如何借鉴 CS:APP 的实验方法

输入错误统一使用中文解释：未知 lab 子命令和笔记主题提供近似拼写建议，参数数量、类型和范围错误显示对应命令的用法，避免直接展示 argparse 的内部命令清单。Bash 的 command_not_found_handle 提供常用命令及漏空格提示，仍返回 127。所有建议只展示，不自动纠正执行，不根据错误输入读取关卡答案。已启动的 Linux 命令保持原生错误输出，不用包装器替换真实命令。程序未预期的异常显示简短反馈；维护者明确设置 `ORBIT_DEBUG=1` 时才输出 Python 调用栈。

第三关新周目包含六个共同前缀和后缀的清理目标，其中一个中间为空，另有同前缀不同后缀、同后缀不同前缀以及隐藏的保留文件。默认任务给选择规则，不给完整模式；提示逐步引入 `*`、预览匹配范围及实际写法。判题检查全部目标已清理、保留文件原样存在，不读取命令历史来强制某种解法。旧存档缺少 `cleanup_version` 时保持原两目标规则；不向玩家现场或旧检查点追加文件。通配符教学是本项目补充设计，不声称已核实原视频讲过该内容。

- **Bomb Lab**：阶段锁定、每阶段独立判定、完成后进入下一阶段；本实验把字符串答案扩展为文件状态、配置和真实权限。保留通关仪式，取消扣分爆炸和时间压力。
- **Shell Lab**：官方 trace 从简单案例逐渐过渡到复杂组合。本实验先单一目标，再多条件判定，最后检查整个交付包。
- **Linux Bootcamp**：官方入门 Lab 本身就使用故事、目录探索与 Vim；本项目采用相同教学方向，但重写场景、文件与校验逻辑。

参考链接与核实范围见 [SOURCES.md](../research/SOURCES.md)。没有使用受限的 CMU 教师题解或评分服务器。

## 循序渐进的安排

第 1 关只给 `ls` 作为起步命令，保留目录用途与返回气闸提交的情景要求，让学生自行探索后续操作。第 2～4 关提供产物、路径与保全要求，不提供命令步骤。第 5～7 关需要把上一关线索带到下一关；任务只给资料位置和目标状态，日志筛选方法、Vim 按键、权限数值与执行语法留在主动求助中。第 8 关只给启动练习进程所必需的 `lab load`，由学生自行观察进程。第 9 关给资源清单与最终包的验收要求，不给顺序化的加工步骤，考查迁移与组合。

三级提示分别回答“往哪看”“用哪种方法”“命令怎么组织”。提示不自动显示；即使第三层也保留每局随机的现场数据，避免只粘贴固定通关密码。判题接受等价操作，不通过扫描 shell 历史强制特定命令；因此教师若要考查 Vim 使用，需要观察编辑过程，不能只看报告。

每关通过后统一显示“本关知识”和“参数与用法说明”：前者概括本关概念，后者简短解释选项名称、行为和对使用者的好处。主动查看的提示与命令卡也就地说明参数，不向默认任务添加解题步骤。非首字母选项区分实际长选项与记忆法，Vim 按键、权限表达式不混称为 Shell 选项。反馈不声称观察到了玩家使用的命令，不把示例用法当作已执行操作。失败时输出首个具体缺项，避免一次堆出大量诊断；可重复检查。`lab repair` 保存原现场并恢复本关起点，避免一个误删让新手必须重做全局。

建议课时：启动与第 1～3 关 15～20 分钟，第 4～7 关 20～30 分钟，第 8～9 关 15～25 分钟，复盘 10 分钟。这是设计估计，尚无课堂试验数据。

## 判定与报告

判题器不运行学生提供的任意代码，也不从学生包自动提取文件。最终包只读取成员并检查路径、类型、重复成员、配置、名单、回执、权限；拒绝路径穿越、链接和额外交付文件。归档内容错误时，外部文件已改好也不能通过。黑匣子原件与备份在最终检查时再次核对。

程序能确认第 1 关提交时的当前工作目录、第 7 关生成的有效回执和第 8 关本局活进程身份，不能保证学生使用了 ls、cat、Vim 或 top 的具体过程；读取存档或调用内部接口也能绕过自学挑战。反馈与报告不是命令审计，也不证明独立完成、长期记忆或教学效果。

练习目录使用独立周目，支持多个周目保留。检查点记录阶段开始时的完整站点，修复会把原站点保存到 recovery。低占用探针上限 90 秒，停止时通过 PID、启动时间、命令行令牌确认归属，并在支持的 Linux 上使用 pidfd 防止误杀复用 PID。极旧内核不支持时让探针自然超时。

## 教师使用与验证

Windows 用户可发 `dist/orbit-lab-handout.zip`，解压后双击 `安装环境.cmd`，准备好后双击 `启动实验.cmd`；Linux 用户可使用 `dist/orbit-lab-handout.tar.gz`，解压后运行 `bash setup.sh --install` 与 `bash start.sh`。环境要求见 [SETUP.md](SETUP.md)。参考流程在 `tests/test_lab.py`，不放进学生包。公开教学文件可以在需要时自行增删。

运行 `python3 -m unittest discover -s tests -v` 做 WSL 集成回归。测试使用临时 Linux 目录，调用真实 Bash、GNU 命令、Vim、top 和 CLI，并用 PTY 检查交互启动与 Vim 的真实按键流程。测试数据与用户周目分开，不会消耗学生进度。结果记录在 [VALIDATION.md](../VALIDATION.md)。

最终 JSON 可收集作为作业附件，重点看完成阶段、失败诊断与提示使用。当前不含登录、联网排行榜或自动提交服务。
