# 本地 AI 配置、情境生成与学习记录

默认新周目先由模型询问兴趣，再按回答生成情境；程序根据固定任务合同编译并校验材料，另发请求复核语义。合格实例建立真实文件后，Linux 操作、本地提示和判题离线运行。已有周目直接续学，不再发起兴趣问询或生成请求。模型负责创作故事和辅助概念讲解，不负责判题，也不会执行你的命令。

本文中的 `lab`、`lab notes`、`lab tutor`、`lab notebook`、`lab review`、`lab tracking` 等都是本平台功能，不是 Linux 通用命令。`lab notes` 的命令名来源、参数原词、用法与记忆联想保留为中文补充知识；同时鼓励看原生帮助，如 `cp --help`、`man cp`、Bash 的 `help cd` 和 Vim 内的 `:help`。原生手册的可用性取决于本机工具与手册页是否安装。

## 在进入实验前配置 API

在程序目录运行以下命令之一，会创建 `ai.local.json` 并显示完整路径：

- WSL/Linux：`python3 orbit.py ai init`
- 已安装 Python 的 Windows PowerShell：`python orbit.py ai init`
- 已在实验终端中：`lab ai init`

已有配置文件不会被覆盖。用文本编辑器打开本地 JSON 文件填写配置，不必把密钥写入命令行。

| 字段 | 含义 |
| --- | --- |
| enabled | 配好后改为 `true`；设为 `false` 禁用模型请求 |
| base_url | 服务商的 Chat Completions API 根地址；可包含 `/v1`，也接受完整 `/chat/completions` 地址 |
| api_key | 你自己的 API 密钥，保留在本地文件中 |
| model | 服务商实际提供的模型标识，按你的账号填写 |
| timeout_seconds | 单次请求超时，1～60 秒，默认 20 秒 |

程序使用 Bearer 认证和 `messages` 格式，调用 `/chat/completions`，不依赖第三方 Python 库。示例地址为 DeepSeek；其他兼容服务需按其文档填写地址和模型。协议参考：[DeepSeek 对话补全接口](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion)。不保证所有声称兼容的服务都能正常返回。

对 `api.deepseek.com`，程序显式关闭思考模式并启用 JSON 输出，以便在有限回复长度内获得结构化结果；其他兼容地址不附加这两个专有参数。依据：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

默认只接受 HTTPS；本机 `localhost`、`127.0.0.1`、`::1` 可用 HTTP。默认拒绝重定向。需要放到程序目录以外时，可在启动前设置 `ORBIT_AI_CONFIG` 为配置文件路径。不要在地址中放密钥。

`lab ai status` 只检查配置格式，不发送请求，也不显示密钥。进入前可用 `python3 orbit.py ai status`，Windows 对应 `python orbit.py ai status`。配置文件已列入 Git 忽略规则，学生发行包只包含空白示例 `ai.example.json`。Linux 下创建时权限为 600；Windows 挂载盘的访问权限仍由 Windows/挂载设置决定。

## 先问兴趣，再进入真实任务

1. 首次运行 `bash start.sh`，或用 `bash start.sh --new` 开新周目。
2. 程序调用配置的模型生成一个简短兴趣问题，你自由描述想体验的题材。
3. 程序提供固定任务合同，模型创作主题对象的语义名称、ASCII 词干，以及每个任务标识对应的动机与进展。
4. 本地程序编译出实际名称和材料，检查结构，再以独立请求复核故事是否贴题、任务关系是否合理、有无超出合同的要求。
5. 通过后冻结实例、合同版本和哈希，创建真实文件并进入 Bash。题面由场景叙事与本地技术要求组合，操作与提交由你完成。

兴趣问询或生成失败时会显示原因。候选场景未通过结构检查或语义复核时，最多根据诊断重新生成一次；仍失败则中止，不会悄悄改用默认故事或替换已有周目。配置缺失时先填写本地文件，再重新启动。复核是另一次模型调用，不是人工专家审核，也不保证发现所有语义问题。

需要离线开始时，可显式指定本地情境：

```bash
bash start.sh --new --scene space
bash start.sh --new --scene ./my-scene.json
```

内置 `space`、`ocean`、`museum`、`anime` 是空间站、深海观测站、数字档案馆和原创星绘学园四个离线示例，不是可生成主题的白名单。已有周目直接运行 `bash start.sh` 恢复原故事、文件映射和进度，不重复联网询问兴趣。

## 导出与切换情境

```text
lab scene
lab scene --generate "山村气象观测队" --output ./my-scene.json
lab scene ./my-scene.json
lab scene museum
```

`--generate` 根据自由描述生成，经过编译、结构检查与独立语义复核后导出完整 JSON；省略 `--output` 时程序自动选择保存位置并显示路径。已有文件不会覆盖。该命令只导出情境包，不改当前周目；生成失败不保存替代包。

在已有周目运行 `lab scene 名称或JSON文件`，会切换完整故事、关卡标题、进展和结局，文件名与学习进度保持当前周目的设置。这是在当前实例上切换叙事，不是重新生成练习材料。要让实际文件采用新主题命名，退出后到项目目录执行 `bash start.sh --new --scene 名称或JSON文件`。新周目会保存完整包与映射快照，之后不依赖原 JSON 文件继续存在。

任务合同固定九个稳定标识及其目标、知识点、证据和依赖。新生成方案只让模型填写 12 类中性任务对象的语义名称与 ASCII 词干，并按任务标识给出动机和进展；模型不直接决定 34 个最终路径、目录拓扑或判题规则。本地编译器产生完整名称映射、题面和材料，所有文件与归档读写使用同一份实例数据。

加载和编译会检查包的字段与长度、名称冲突、路径安全、隐藏属性、扩展名和控制字符，不执行 JSON 内容。生成后的独立复核关注语义贴合、任务关系和不必要的复杂信息；结构与语义分别检查，复核模型仍可能漏判。旧本地情境包继续使用兼容加载方式，不能因此被表述为已经过本轮模型复核。

根目录 `station`、隐藏标记 `.beacon-*`、清理模式 `decoy-*.tmp`、探针名 `station-pulse` 和配置字段属于固定教学协议。新生成实例使用中性的 `MODE=active` 与 `MODE=deliver`；旧周目、旧离线包兼容 `rescue` 与 `evacuate`。请以本局任务为准。所有主题共享相同知识点与检查要求，模型无权改写这些条件。

## 练习中的个性化求助

```text
lab concepts
lab tutor
lab tutor "相对路径从哪里开始计算？"
lab tutor --topic paths --level 2
lab tutor --offline
lab notebook
lab review
```

`lab tutor` 根据最近的检查失败或其后尚未解决的具体输入问题选择关联知识点；没有问题记录时从本关知识点开始。`--topic` 可指定 `lab concepts` 列出的本关知识点。三级提示依次给方向、方法、单步骨架；对象由你观察确定。`lab hint` 始终离线，也会针对当前问题提示。

概念求助时，AI 返回简短概念解释，单步提示由本地教学资料提供。当前关有具体输入错误记录时，另让模型根据记录编号和重复模式提出候选原因、引用证据及验证目标；终端标为“AI 待验证解释”，不将模型判断记为已确认的学习事实。程序检查返回格式、长度、控制字符、当前答案、命令片段和证据引用是否存在。不合格式、联网失败、超时或未配置时，`lab tutor` 自动回到本地解释。这个回退仅适用于求助；它不把情境生成失败包装成成功。引用存在不代表解释正确。

## 何时联网、发送什么

| 入口 | 发送内容 |
| --- | --- |
| 新周目兴趣问询 | 让模型提出兴趣问题的固定说明；不发送旧周目数据 |
| 回答主题后生成，或 `lab scene --generate` | 你填写的主题、任务合同摘要、允许填写的语义角色与格式约束；重生成时另含失败诊断 |
| 独立语义复核 | 候选场景与任务合同摘要，用于核对主题、任务动机和约束；不发送学生答案 |
| 未指定 `--offline` 的 `lab tutor` | 当前诊断类别、候选原因、知识点摘要、操作依据、相关学习计数、提示级别和本次问题；有具体输入问题时附最多12条记录摘要、编号及重复/修正计数，可能包含筛选后的错误命令词、选项或实验内路径片段 |

只有配置启用且有效时才会发送模型请求。普通 Linux 操作、判题、本地提示、手册、复习、已有周目续学和显式加载本地情境均不请求模型。

程序不上传整个存档、学生文件、判题源码、原始操作记录、Bash 历史或终端输出。密钥仅用于配置服务的认证头，不作为正文发送。概念求助会遮盖已知的本局随机答案及常见密钥字段；情境生成会遮盖意外写入主题的当前配置密钥。自动遮盖不能识别所有敏感内容，请勿在主题或问题中输入私人资料。服务方如何保存请求取决于其政策。

本地模拟服务用于检验请求、校验与失败处理；真实服务试验另用于观察实际响应，结果以仓库的 `VALIDATION.md` 为准。两者都不能证明所有题材质量、学习迁移或教学效果，模型复核通过也不是此类证明。

## 学习手册与复习

检查失败同时显示观察结果、关联知识点、待核实的可能原因和一个观察步骤。检查或求助后，本局目录中的 `learning-notebook.md` 自动更新；用 `lab notebook` 查看，也可根据显示的文件路径使用 `cat` 或 `less` 阅读。手册不包含随机凭证或答案，也不把通过检查换算成掌握百分比。

`lab review` 优先列出到期、关联检查问题和输入尝试段较多的已遇到知识点。例如 `lab review paths` 显示一个与本局答案无关的小题，看题后用 `lab review paths A` 作答。答错会解释概念并保留复习需要，答对按 1、7、30 天建议下次复习。同一天反复作答不会累计多个间隔复习里程碑。这个间隔是简单规则，未验证为个人遗忘曲线，不自动跳过关卡。

退出后再次启动保留进度、诊断、提示级别、情境快照、文件映射和复习记录。旧周目无需重开；此前没有结构化记录的错误不会被补写成已确认的知识问题。`lab repair` 仍备份现场并恢复本关起点，保留学习记录，清除当前待诊断问题。

## 操作轨迹与证据边界

新周目默认开启本地操作记录，入口会显示范围；`lab tracking off` 关闭，`lab tracking on` 重新开启，`lab activity` 查看。旧周目没有开关字段时，在下次启动采用新默认；已有关闭状态时保持关闭，可手动开启。只观察实验目录内的命令，保留最近2000条有限操作记录，以及最近500条具体问题记录、最多200组问题模式。日常记录不调用模型、不逐条上传。

除命令类别、选项、对象角色、时间、退出码及有限文件状态外，具体问题会保留筛选后的命令词、选项名和实验内相对路径片段。只分析有限的简单语法、ASCII名称与路径元数据，不记录整行命令、原生输出或文件正文；本局随机答案、凭据形式、外部路径和符号链接排除。参数拼写只提出候选，不把本地语法表未覆盖的选项当成无效。缺少原生 stderr 时，不能把观察到的文件缺失断言为唯一报错原因。

实验子 Shell 的历史仅存在内存中供上下键使用，不再新增磁盘原始历史；原有 `history` 文件不读取、不追加、不删除。程序不采集逐键输入、退格、停顿或 Vim 内部按键。配置只保存用于判断磁盘内容是否变化的本地指纹，不保存配置正文。

提示符钩子保留真正重复提交的输入，首次提示符和空回车不算新操作。组合命令、展开、别名、函数和不认识的语法采用保守处理，不完整重建 Shell 行为；返回非零本身不等于犯错，例如 grep 未匹配不能记为知识错误。

`lab notebook` 另列具体输入问题、发生位置、失败输入次数、连续尝试段和观察到候选修正后成功的段数。同一拼写错误连试三次属于一个尝试段；在相同关卡和目录、其余参数相同的条件下，观察到候选修正后命令成功，再犯时另记一段。查看帮助或参数不同的成功输入不算解决；无法确认修正时不虚构已解决。相同判定现场与相同提交的连续 `lab check` 保留检查次数、合并诊断，不重复增加知识点失败；历史旧计数不反推或改写。以上都是本局观察，不是跨周目的个人能力画像。

有操作证据时，程序把它与之后的检查结合。例如原件到备份的 `cp` 输入使用普通星号模式，随后检查发现隐藏项缺失，会优先解释隐藏项匹配；缺少操作证据时只列候选原因。检查、恢复之间以记录序号划分区间，避免旧操作不断被当成本次依据。Vim 结束后仅能比较磁盘内容是否改变，不能据此宣称观察到了保存按键或推断学生意图。

这里的“连续尝试段”指同一问题尚未观察到结束的一段尝试，中间可以夹有其他命令，并非要求相邻输入。记录有数量上限，问题长期未能匹配到修正时也可能合并在同一段，因此这些统计不能当作全部独立错误的精确计数。
