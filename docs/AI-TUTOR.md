# 如何搭配 GPT / Codex 学习

[学生版助教约定](STUDENT-AGENTS.md)允许讲解、排错和分层提示；不读取内部存档找答案，不代写任务文件，不代交关卡。学生发行包根目录的 `AGENTS.md` 使用这份规则，仅包含助教行为约定。

## 实验内的模型与外部聊天助手

实验内的模型通过程序目录的本地 `ai.local.json` 配置。新周目默认先调用模型询问兴趣，再按你的回答创作任务动机和主题对象名称；本地任务合同与编译器控制技术要求、真实文件和判题，另一次模型调用检查语义贴合。失败最多按诊断重生成一次，仍失败则中止并保留旧局。已有周目续学不再询问或生成。未配置时可以先按[本地 AI 说明](LOCAL-AI.md)填写文件，也可以显式指定 `--scene` 使用离线情境。

做题时的 `lab tutor` 是另一种请求：它根据本局有限学习证据补充概念解释，操作与提交仍由你完成；`lab tutor --offline` 只用本地讲解。这些集成入口不等同于另外打开 GPT、Codex 或其他聊天客户端，外部客户端是否读取规则与如何使用文件仍取决于其自身行为。

## Codex 是否会自动读取

根据 [OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，Codex 启动时建立指令链，先处理全局配置，再按项目根到当前工作目录加载适用文件；找不到项目根时只检查当前目录。它在每次运行/会话启动时加载，不等于每条回复之前重新打开文件。

每层优先 `AGENTS.override.md`，其次 `AGENTS.md`，然后配置的备用名称；更深目录可覆盖前面的指导。空文件会跳过，合并内容默认有 32 KiB 上限。因此请使用大写的标准文件名 `AGENTS.md`，不要依赖 Windows 的大小写不敏感行为。

在本目录启动新的 Codex 会话通常会自动加载该文件，不一定显示一条“读取文件”的工具操作。已有会话中新建或改动了规则，建议新开会话；也可明确要求重新读取。可先问：“请列出当前生效的项目指令，并概括助教模式允许和不允许做的事，不读取题目答案。”这能帮助检查加载情况，但不是严格的遵守证明。

WSL 的实际练习目录在 `~/.local/share/orbit-lab/sessions/.../station`，不属于桌面源码目录的子目录。程序会在**该站点根目录**写入学生版 `AGENTS.md` 并复制学生手册；新局、续玩和现场恢复都使用学生版规则。从源码启动也遵循这一做法。若从练习文件直接求助，请先 `cd "$(lab root)"`，再从该根目录启动 Codex；不要假定从任意任务子目录启动都能继承上层文件，特别是没有 Git 根目录的时候。

## 普通 ChatGPT 或其他客户端

不要假定普通聊天窗口能看见本机文件或自动发现 `AGENTS.md`。手动提供该文件，并说明“请按这份规则担任助教”，再贴当前任务、你的尝试与报错。不要把全量存档或测试通关代码当作题目附件。

## 它的实际保证

这是提示与项目行为约定，不是硬性的访问控制。不同客户端、其他指令、用户修改文件或模型偏离都可能使约定失效。实验内的 API 集成会校验返回格式、路径映射以及概念解释中的部分敏感内容，但不会控制外部聊天客户端，也不是防作弊边界；不能声称它能绝对阻止泄题。当前仍没有独立账号体系或课堂服务器端助教。

如将来需要统一课堂管理，应另做受控助教界面，只提供当前关卡的学生可见信息，并把答案与判题状态放在独立服务。那是另一个系统能力，当前版本没有实现。
